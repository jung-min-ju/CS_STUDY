무슨 패턴인가View는 화면만, Model은 데이터만 담당하고, 모든 로직은 Presenter가 중재합니다. View와 Model이 서로 직접 통신하지 않아 테스트가 쉬워요.
이 화면에서는Model·Presenter·View 세 박스가 흐름 화살표로 연결되어 있고, View와 Model 사이에 직접 연결이 없습니다. "+ 할 일 추가" 버튼으로 Presenter가 모든 중재를 맡는 과정을 확인하세요.
언제 떠올리나View를 Mock으로 바꿔 Presenter 로직만 단위 테스트하고 싶을 때. Android Activity처럼 화면 프레임워크 의존도가 높은 환경에서 특히 유용합니다.
MVP pattern
// View — 화면만 담당 (멍청한 View!)
interface TodoView {
showTodos(todos): void
showError(msg): void
getInputText(): string
}
// Model — 데이터만 담당
class TodoModel {
addTodo(text) { this.todos.push({ text, done: false }) }
toggle(i) { this.todos[i].done = !this.todos[i].done }
getTodos() { return [...this.todos] }
}
// Presenter — 모든 로직의 중심!
class TodoPresenter {
constructor(private model, private view) {}
onAddClicked() {
const text = this.view.getInputText()
this.model.addTodo(text)
this.view.showTodos(this.model.getTodos())
}
}
