무슨 패턴인가실제 객체 대신 대리인(Proxy)을 두어, 접근 제어·캐싱·로깅 같은 부가 기능을 원본 코드 수정 없이 끼워 넣을 수 있습니다.
이 화면에서는Client → Proxy → Real Service 세 박스가 화살표로 연결되어 있고, fetch 버튼을 누르면 Proxy cache 영역에 캐시 여부가 표시됩니다. 같은 ID를 다시 요청하면 Cache hit 카운터가 올라가고 Real Service 호출이 생략되는 것을 확인하세요.
언제 떠올리나비용이 큰 API 호출을 캐싱하거나, 권한 검사를 원본 서비스 변경 없이 추가하고 싶을 때. 이미지 Lazy Loading도 대표적인 프록시 활용입니다.
Proxy pattern (caching proxy)
interface DataService {
fetch(id): Data
}
class RealService implements DataService {
fetch(id) {
return db.query(id) // 느린 DB 호출!
}
}
class CachingProxy implements DataService {
private cache = new Map()
constructor(private real: RealService) {}
fetch(id) {
if (this.cache.has(id))
return this.cache.get(id)
const data = this.real.fetch(id)
this.cache.set(id, data)
return data
}
}
